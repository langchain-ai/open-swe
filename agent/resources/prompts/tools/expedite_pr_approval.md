Post a Slack card asking someone other than the author to approve a tiny pull request instead of a normal GitHub review. Any open pull request qualifies, not only ones you opened, and you do not need to be asked: nominate a qualifying pull request on your own.

Use it only for a change of at most 20 lines in ordinary text files that a reviewer can judge from the diff alone. Test files do not count toward that limit, so send the tests along with the change. Never for auth, secrets, CI workflows, dependency manifests, migrations, or binaries; those are refused. Do not mark a draft ready yourself: for a draft, the card asks the pull request's author to mark it ready from Slack before anyone can approve.

The card is posted right away, whether or not checks have finished. One approval from someone other than the author is enough, and it is submitted as that person's GitHub review as soon as they click; you merge with `merge_expedited_pr`. Keep a `/baby-sit` watch on the PR so you know when checks are green, and call `merge_expedited_pr` then. You are also woken when someone approves the card; a dismissal only closes it, and anyone who wants changes tags you in the thread. A later commit that touches only tests keeps the approval. When one changes the diff shown on the card, `merge_expedited_pr` lets you judge whether the approver needs to look again; call this tool again for a fresh card only when they do. Calling it again for an unchanged diff does not post a second card. Use `action="cancel"` to withdraw a card you no longer want.

The card goes in the current Slack thread when there is one, and naming that thread's own channel changes nothing. Pass `channel` (a Slack channel name like `#eng-reviews` or a channel id) to post it as a new thread in a different channel; this is required when the conversation is not in Slack.
