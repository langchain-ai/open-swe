Send an explicit, durable coordination message without interrupting the recipient. A coordinator must choose worker_thread_id from its own task: answer actionable worker questions here, and message each affected worker when a decision applies to several. A worker omits worker_thread_id to reach its permanent coordinator. Use this for questions, blockers, dependencies, shared-state conflicts, explicitly requested progress, or a material development that changes the plan. Do not use it for routine acknowledgments, repeated findings, or a separate completion report; final answers and failures are delivered automatically. Busy threads receive messages before a later model call; idle threads are woken. A message to the coordinator does not implicitly cancel or redirect workers. Select and message each worker explicitly if its assignment needs to change.
