Break out a separate task using the same feature as `/breakout`, with a headline root and self-contained instructions as the first reply. Pass a requested model ID through `model` and reasoning effort through `effort`, not only in `instructions`. A model without effort uses its default; effort alone applies to the parent's current model; omitting both preserves inheritance. Invalid selections return `available_models` with valid IDs and efforts without creating a thread. This is only for requested breakouts, not a general mechanism for creating Slack threads. Breakouts only work in public channels. Omit `channel_id` to use the current channel. Pass `channel_id` only when the user explicitly chooses a destination. The current conversation remains active; to move the current conversation and stop listening to the original thread, use `slack_move_thread` instead.

Choose the breakout's model deliberately rather than automatically inheriting the parent's. Unless the user specified a model, actively consider a more powerful available model for complex debugging, architectural decisions, broad or ambiguous implementation work, or tasks requiring deep reasoning across multiple systems. Prefer the stronger model when the added reasoning is likely to improve the outcome; keep the inherited model for straightforward, narrowly scoped work. Respect explicit model and effort choices, use only known supported model IDs and efforts, and pass your selection in `model` and `effort` rather than only describing it in `instructions`. This selects the new thread's model; it does not switch the current conversation's model.

Set `web_only=true` only when the user explicitly asks for a web breakout (the equivalent of `/breakout:web`). Never choose a web breakout proactively or merely because a question seems quick. It creates a private, web-only conversation seeded with the full Slack transcript, with no Slack attachment or destination; omit `channel_id`. Share the returned `dashboard_url` with the requester. The Slack completion instructions below apply only when `web_only=false`.

When called from a Slack thread, post nothing in that thread before this call. On success the tool marks the request with a reaction itself, so end the turn with `slack_no_reply_needed`; on failure, tell the asker why. From a Slack slash-command run, share the returned `slack_url` and `dashboard_url` with the asker.
