Drain the event queue `subscribe_thread_events` opened: wait up to `wait_seconds` (at most 30) for its threads to log new events, then return them oldest first and advance the queue past them. It returns as soon as there are events, so call it in a loop to tail a conversation. Every event has its `thread_id`, `version`, `type` and a `data` object with the event's fields; long text is cut short, so use `get_thread` for the full transcript. `threads` reports each followed thread's `status`. A thread is done working when a `turn.completed`, `turn.failed` or `turn.interrupted` event arrives and its status is no longer `running`. `has_more` means `limit` cut the batch short and the next call returns the rest at once. `dropped` lists threads the queue stopped following because they were deleted or you lost access.
