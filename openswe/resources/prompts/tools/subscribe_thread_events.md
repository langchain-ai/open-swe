Start following threads, like `gh run watch` or `tail -f` for Open SWE conversations. Accepts the same thread locators as `get_thread` and opens a server-side event queue, or adds the threads to the queue named by `queue_id`. Each thread is followed from its newest event onward, so subscribe before calling `manage_thread` to send a message you want to watch. Then call `select_thread_events` with the returned `queue_id`, again and again, to drain what happened. `event_types` picks which transcript events the queue hands out. It defaults to turn lifecycle events (`turn.requested`, `turn.queued`, `turn.started`, `turn.completed`, `turn.failed`, `turn.interrupted`) and finished messages (`message.completed`); `message.appended` streams partial text and `tool.started`/`tool.completed` show tool calls. Subscribing again to a thread the queue already follows changes its event types and keeps its place. Each returned thread has a `status` (`running`, `idle` or `error`). A queue unused for an hour expires.
