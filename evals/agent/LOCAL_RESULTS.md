# 本地验证与简历表述（2026-10-20）

这次工作是在 Open SWE 现有代码基础上，完善编码 Agent 的评测与故障诊断，
并按“环境标准化 → 超时取消 → 失败回归 → 幂等一致性”推进运行可靠性改进。
当前证据能支持工程功能已经实现，尚不能支持模型成功率或推理成本改善。

## 已实现的改进

- 通过图状态返回 Git 补丁，包含已提交修改和新文件，替代让模型再次输出 diff；
  每题只发起一次编码 run，文件下载避免 shell 输出截断。
- 将执行、补丁收集、依赖安装、测试执行、目标测试失败和回归等问题划分为
  12 类失败阶段，保留完整输出、测试退出码、缺失测试和阶段耗时。
- 支持本地 JSONL 运行，固定任务快照与 SHA-256 指纹，保存原始预测、逐题结果和
  汇总报告。执行失败仍计入成功率分母，未知用量不会被当作零。
- 支持两组模型实验按题比较；拒绝缺题、重复记录、未完成运行、任务或评分策略
  不同的比较。参考补丁与空补丁自检不能混入模型性能报告。
- 记录沙箱内的实际操作系统、shell、解释器、目录和 Git 信息，并注入相应命令
  指导；评分器默认使用自身解释器，避免 PATH 指向缺少 pytest 的系统 Python。
- 加入可随 checkpoint 恢复的主 Agent 模型/工具共享时间预算；本地命令原生异步
  执行，限制输出保留量，超时保留部分输出，取消时清理进程树。评分器也覆盖进程树清理。
- 支持显式冻结失败案例并回放评分，检查修复结果和失败阶段是否漂移，不额外调用模型。
- 加固 Slack 消息入口去重：原子领取、写入回读确认、缓存过期、远端请求超时；
  存储不可用时返回可重试状态，外层处理器保留 503，慢事件不占用缓存全局锁。

实现、配置及保证范围见 [AGENT_RELIABILITY.md](../../docs/AGENT_RELIABILITY.md)。

## 已验证的事实

最初本地运行与实验比较阶段的相关回归为 148 项通过。这轮加入运行可靠性后，
最终相关测试为 **221 项通过**；Ruff 检查、格式检查和改动 Python 文件的类型检查通过。
没有运行项目全量测试。检查日志：`artifacts/reliability-final-verified.log`。

新增验证覆盖真实命令的大输出、超时前日志、取消后子孙进程无法延迟写文件、
正常启动后台进程、图内模型与工具的取消传播、checkpoint 恢复、未知环境探测、
结构化系统上下文保留、存储故障恢复及 webhook 503 透传。
也修正了 pytest 误收集一个已导入配置函数的问题，避免将其算作行为测试。

另外，对本地临时 Git 仓库实际执行 checkout、应用补丁和 pytest：

| 输入 | 结果 | 含义 |
|---|---|---|
| 参考补丁 | resolved=true | 修复目标测试，保留已有测试 |
| 空补丁 | no_patch | 目标测试失败，已有测试继续通过 |
| 尝试比较上述两组 | 拒绝 | 自检结果不被计为模型实验 |
| 冻结空补丁并回放 | matched=true | 历史预测重复评分，仍归为 no_patch |

上述是评测器自检，没有调用模型。自检报告保存在忽略目录：
`artifacts/local-eval-reference/`、`artifacts/local-eval-empty/`。
最终回放证据在 `artifacts/replayed-empty-regression-final/expectations.json`。
任务集指纹为 `f199c69e185c201d80eddec40e85f3e781e91001816f75d4c7ef2993e3568460`；
临时仓库的本地 URL 属于该快照，换机器后需要重新生成任务集和指纹。

回放还暴露了评分器误选解释器的问题：没有 pytest 的系统 Python 导致测试无法执行，
从而改变失败分类。固定解释器后完成真实回放，并新增了 PATH 中不存在 Python
时仍能使用评测器环境的进程测试。Windows 命令取消最初依赖 `taskkill` 时出现
权限错误、子进程仍继续写文件，改为 Job Object 后通过进程树取消测试。

本地 Ollama 模型列表和 Agent `/ok` 接口可访问，但读取既有 Agent 线程超时。
本次没有新的端到端模型实验，没有可用于声称“成功率提升 X%”的数据。
此前单题模型运行见 [SMOKE_RESULTS.md](SMOKE_RESULTS.md)，不能与本次自检作性能对比。

## 现在可以使用的简历写法

**Open SWE 编码 Agent 评测与运行可靠性优化｜Python、FastAPI、LangGraph、pytest、Git**

> 基于 Open SWE 完善编码 Agent 自动化评测链路，使用隔离 Git checkout 和目标/
> 回归测试判定修复结果；实现图状态补丁采集，替代二次模型生成 diff。
>
> 设计 12 类失败阶段及结构化诊断，保留退出码、完整日志、缺失测试与阶段耗时；
> 构建任务集指纹和逐题实验对比，校验样本完整性与评分策略一致性，支持问题复现。
>
> 实现可恢复的调用时间预算与异步命令取消，结合进程组/Windows Job Object
> 清理子进程；支持失败案例冻结回放，并加固 webhook 入口去重及故障重试，
> 通过 221 项相关行为与回归测试。

投后端岗位时可以突出异步执行、子进程超时清理、类型约束和可观测性；
投 Agent 应用岗位时可以突出工具产物采集、确定性评分、回归保护和实验可信度。
这里描述的是个人新增改进，不应表述为独立开发整个 Open SWE 平台。
四个方向均为首版：环境探测尚未实现固定容器；共享预算未包住全部准备阶段；
回放不重演模型轨迹；入口去重仍存在领取到任务执行的崩溃窗口，不能声称
端到端 exactly-once、“不丢不重”或覆盖 PR/评论等全部外部副作用。

## 后续需要补齐的实验

1. 准备 10–20 个有参考解的真实仓库任务，覆盖工具调用、文件修改和测试修复。
   每题先验证参考补丁通过、空补丁失败，并记录依赖和运行环境。
2. 恢复 Agent 线程接口，在固定沙箱和模型版本下运行 baseline，每组至少重复
   3 次；只改变一个待验证因素，例如工具反馈格式或提示词。
3. 使用配对报告检查新增成功、回归和失败阶段迁移，再根据实测结果补充成功率、
   耗时和有效用量覆盖率。小样本结果注明题数与重复次数。
4. 为入口任务补齐持久化投递、重启恢复及外部副作用幂等记录，再验证领取成功后
   进程崩溃的恢复路径；当前入口去重测试不替代这一验证。
